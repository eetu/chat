# Chat — repo overview

Self-hosted chat UI for an Ollama endpoint on the LAN. Sibling product to halo
(`../hcc`); shares the design system but is a separate Rust + React app.

## Layout

```
backend/         actix-web 4, SSE proxy → Ollama, SQLite, OIDC (kanidm) auth
frontend/        Vite + React 19 + Emotion + TanStack Router (file-based)
.claude/skills/  chat-design skill (visual language, brand)
```

Per-area instructions live in `backend/CLAUDE.md` and `frontend/CLAUDE.md`.

## Conventions

- **Auth model.** All `/api/*` routes (except `/api/me`) require a session
  cookie. The session is set either by `/auth/callback` (OIDC, kanidm) or, in
  dev, by `/auth/login` directly when `DEV_AUTH=1`. There are no admin roles —
  every authenticated user sees only their own data, scoped by the `sub` claim.
- **Per-user data isolation.** Every storage method takes `user_sub` and
  returns `NotFound`/`Forbidden` when a row's `user_sub` mismatches. Never
  expose a route that lets one user enumerate or fetch another user's
  conversations.
- **TTL.** Conversations are purged hourly when `updated_at` is older than
  `CHAT_TTL_DAYS` days (default 30). Cascade deletes the messages.
- **Streaming.** `/api/chat` returns SSE (`text/event-stream`) with three event
  types:
  - `delta` — body is the raw text chunk (NOT JSON). Concatenate to render.
  - `done` — JSON `{ conv_id }`. Use to hide the loading indicator.
  - `error` — JSON `{ message }`.
- **Retrieval.** Two sources feed the model: RAG over the user's
  uploaded documents (always on when embeddings are configured) and web
  search (opt-in per turn via the composer toggle). Both inject one
  `system` message and report through one `context` SSE event, and both
  persist their citations on `messages.sources`. Web search is
  deterministic pre-retrieval — it does **not** use Ollama tool calling,
  which is still out of scope below.
- **Web search has no upstream service.** It runs in-process via the
  `daedra` crate across unkeyed backends — no API key, nothing to
  deploy, and no query leaving for a third-party search vendor beyond
  the engines daedra queries. Fetching pages is done only by
  `backend/src/safefetch.rs`, which refuses any non-public address; see
  `backend/CLAUDE.md` before touching either.
- **Design system.** Tokens are copied verbatim from halo's `themes.ts`. Don't
  fork them — when halo evolves, copy the file across so the two apps stay
  visually aligned. The only intentional divergence is `Wordmark.tsx`.

## Working on this repo

- Backend lives at `:8080`. Frontend dev server (`yarn dev`) at `:5173`,
  with Vite proxying `/api`, `/auth`, `/status` through.
- Use `DEV_AUTH=1` for local development — kanidm isn't required.
- The TanStack Router `routeTree.gen.ts` is regenerated by the Vite plugin
  on every dev/build. The committed copy is a stub so the project type-checks
  on a fresh clone before the plugin runs.

## Out of scope (for now)

- Tool use / function calling on Ollama side. The `tools` capability is
  read from `/api/show` and reported by `/api/models/caps`, but nothing
  sends a `tools` array or parses `tool_calls`. Web retrieval exists
  without it — see "Retrieval" above.
- Multi-modal (images/audio)
- Shared/team conversations — strictly per-user
- Admin UI

If a feature crosses into those areas, raise it before implementing.
