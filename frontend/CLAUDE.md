# Frontend

Vite + React 19 + Emotion + TanStack Router (file-based) + SWR.

## Validation

```sh
yarn validate    # lint + format + typecheck in one shot
yarn dev         # vite dev server on :5173, proxies api/auth/status to :8080
yarn build       # tsc + vite build → dist/
```

Use **yarn** (not npm). Repo uses Yarn 4 via `packageManager`.

Individual:
- `yarn lint` / `yarn lint:fix`
- `yarn format` / `yarn format:fix`
- `yarn typecheck`

## Conventions

- **Theme tokens.** Always read from `useTheme()` — no hardcoded hex codes
  outside `themes.ts`. The theme keys mirror halo's; learn them once.
- **Don't fork `themes.ts`.** It is copied verbatim from halo. When halo
  evolves the design tokens, copy the file across again. Wordmark.tsx is
  the only intentional divergence.
- **TanStack Router.** Routes are file-based; the plugin regenerates
  `routeTree.gen.ts` on every dev/build. The committed file is a stub for
  type-checks on a fresh clone — don't hand-edit (it'll be overwritten).
- **Responsive.** Single breakpoint at 600px. Use
  `useMediaQuery("(max-width: 600px)")` (from `usehooks-ts`) in components
  for layout switches; use `mq[0]` from `src/mq.ts` inside emotion css for
  media-query overrides. Keep the two definitions in sync — only one
  number, only one place.
- **Sidebar visibility.** Single `open` boolean in `__root.tsx`, default
  `!isMobile`. When `false` on desktop the sidebar is `display: none`
  (main expands); on mobile it slides off-canvas. A floating circular
  hamburger appears in the top-left of `<main>` when `!open`. The
  sidebar's own `chevron_left` button calls `onClose` to hide it.
- **SWR** for cached GETs (`/api/conversations`, `/api/me`). After mutating
  state on the server, call `mutate("/api/conversations")` to refresh.
- **Streaming.** `api.streamChat()` is an async generator yielding typed
  `ChatStreamEvent`s. Call from `useChat`; never bypass to subscribe to the
  raw `ReadableStream`.
- **No emoji** in UI strings. Brand voice is lowercase, terse, mildly pulpy.
  ("you brought a knife to a gunfight. sign in first.")

## Auth gate behavior

`<LoginGate>` calls `/api/me` on mount. On 401 it renders the sign-in screen
that links to `/auth/login`. Successful sign-in (dev or OIDC) returns the
user to `/`. SWR re-fetches `/api/me` automatically when the gate re-mounts.

## Streaming render

The assistant message bubble is appended optimistically with empty content
the moment a user sends. As `delta` events arrive, content is concatenated
in place. On `done`, SWR refreshes the conversation list (so titles update
when the backend renames a conversation from `"new chat"`).

## Don'ts

- Don't introduce a global state library (zustand/redux). SWR + local state
  is enough.
- Don't render markdown for **user** messages — keep them plain
  `white-space: pre-wrap`. Markdown is assistant-only by design (avoids
  rendering accidental backticks in user prompts).
- Don't enable `rehype-raw` in `Markdown.tsx`. Raw HTML in model output is
  intentionally escaped, not rendered.
- For markdown extensions (mermaid, slugs, emoji, code-copy button,
  streaming-fence balancing) see `.claude/skills/chat-design/README.md`
  → "Future renderer extensions". Each entry has its install command,
  plugin/component snippet, and the tradeoff that justified deferring it.
  Don't add speculatively — wire when a real conversation needs it.
- Don't add hover-only affordances. Some users will be on touch devices.
